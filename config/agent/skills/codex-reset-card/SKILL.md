# 定时使用 Codex 重置卡

通过本机已登录的 `codex app-server` 查询卡片，用 Linux 用户级 systemd timer 在指定时间兑换。保持明确的卡片 ID、一次逻辑操作一个幂等键、有限执行窗口和可检查的回执。

## 先查询和确定范围

1. 查看 `codex --version`，执行 `python3 -B scripts/reset_card.py --list`（脚本路径相对本 skill 目录）。这是只读操作，输出额度和卡片明细。
2. 列出可用卡片的 ID、状态、到期时间及当前额度窗口。`availableCount` 可能大于返回的明细数量；`credits: null` 表示还没有明细，不能凭数量猜卡片 ID。协议见 [references/protocol.md](references/protocol.md)。
3. 从用户意图确定使用哪张卡、哪天几点和时区。可以落实明确的“最早到期的一张”策略；只给时间或有多张候选且无法推断选择时，用简短问题补齐。按用户时区把相对日期转换成带 UTC 偏移的绝对时间，并核对早于到期时间。
4. 查看已有 `codex-reset-card-*.timer` 及其配置，避免给同一张卡重复建任务。已有任务应查状态、取消或改期，保留原幂等键和历史。

## 准备和启用

用户要求定时使用即授权设置这一张卡的任务；不必再重复确认。仅要求创建/修改 skill、只读查询或草拟计划时，不执行兑换，也不启用任务。

在实际要运行任务的机器上准备：

```sh
python3 -B scripts/prepare_timer.py --credit-id '实际卡片 ID' --at '带偏移的 ISO 8601 时间'
```

脚本只读查询并生成配置、私有环境文件、service 和 timer，返回 `armed: false`。它拒绝覆盖已有任务；到期时间为 null 的卡也受有限执行窗口约束。默认最多重试八分钟，超过卡片到期时间立即停止。

按照 [references/timers.md](references/timers.md) 完成只读预检、unit 校验和启用，并验证系统实际记录的触发时间。使用用户级 systemd，不依赖当前对话、临时 sleep 或 tmux 存活。当前生成器仅支持 Linux；其他系统先使用对应的持久调度器，不能把 Linux 文件生成成功当成已安排。

代理必须进入实际执行进程及其子进程，大小写变量一并继承，包含已有的 NO_PROXY。脚本从当前环境复制配置；若本机代理仅配置在 shell 文件或另一应用内，先读取本机配置补到启动环境。环境文件权限为 0600；回报变量是否存在，不输出代理地址、凭据或环境文件内容。

## 执行和回报

- 执行器仅在有效时间窗口内提交指定 ID。每次重试复用保存的 UUID；不换卡、不新建幂等键、不删除 attempt 或 receipt 来“重试”。文件锁防止并发兑换。
- 读取 `receipt.json` 的原始 `outcome`：`reset` 表示本次已重置；`alreadyRedeemed` 表示同一幂等请求此前已兑换；`nothingToReset` 表示没有需要重置的窗口；`noCredit` 表示没有可用卡。后两者结束本次任务，不能报告“已使用重置卡”。
- 连接中断且没有确定回执时，报告结果待确认。只在同一卡、同一幂等键和原执行窗口内恢复；先查状态，避免把未知结果当作失败重新消费。
- 提交后的刷新用于验证当前额度，刷新失败不重新兑换。timer 触发、service 退出码为 0、日志出现 `verified` 都不能代替兑换回执。
- 查询/取消/改期步骤及保留哪些证据见 [references/timers.md](references/timers.md)。取消后核对 timer 和 service 状态；已被服务端接受的请求无法用停止 timer 撤回。

完成安排时给出卡片选择、用户时区的执行时间、到期时间、任务名和配置/状态目录。只有验证 timer 已启用且时间正确后才说“已安排”；实际是否使用以执行后的回执为准。
