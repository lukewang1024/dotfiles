# 使用 Codex 重置卡

通过本机已登录的 `codex app-server` 查询卡片，用 Linux 用户级 systemd timer 在指定时间或每周额度归零时兑换一张。保持明确的卡片 ID、一次逻辑操作一个幂等键、有限执行窗口和可检查的回执。

## 先查询和确定范围

1. 查看 `codex --version`，执行 `python3 -B scripts/reset_card.py --list`（脚本路径相对本 skill 目录）。这是只读操作，输出额度和卡片明细。
2. 列出可用卡片的 ID、状态、到期时间及当前额度窗口。`availableCount` 可能大于返回的明细数量；`credits: null` 表示还没有明细，不能凭数量猜卡片 ID。协议见 [references/protocol.md](references/protocol.md)。
3. 确定使用哪张卡和触发条件：指定时间，或每周额度剩余为 0 时。用户要求“最早到期的一张”时，只有全部可用卡明细齐全才能自动选卡；否则使用用户明确指定且已核实的 ID。指定时间需带时区并早于卡片到期；其他选择无法从用户意图推断时再询问。
4. 查看已有 `codex-reset-card-*.timer` 及其配置，避免给同一张卡重复建任务。已有任务应查状态、取消或改期，保留原幂等键和历史。

## 准备和启用

用户要求定时使用或额度耗尽后自动使用即授权设置这一张卡的任务；不必再重复确认。仅要求创建/修改 skill、只读查询或草拟计划时，不执行兑换，也不启用任务。

在实际要运行任务的机器上，按触发条件准备其中一种：

```sh
python3 -B scripts/prepare_timer.py --credit-id '实际卡片 ID' --at '带偏移的 ISO 8601 时间'

# 耗尽时：默认选择完整明细中最早到期的卡；也可指定 --credit-id '实际卡片 ID'
python3 -B scripts/prepare_watch.py
```

脚本只读查询并生成配置、私有环境文件、service 和 timer，返回 `armed: false`。它们拒绝覆盖已有任务。轮询默认立即开始、之后每分钟检查；自动选卡后固定该 ID，不自动换卡。无到期时间的卡须显式指定 ID 和带时区的 `--until`；有到期时间的卡也可用 `--until` 提前结束监控。真正提交后的恢复窗口默认最多八分钟，且不超过监控截止或卡片到期。

按照 [references/timers.md](references/timers.md) 对相应模式完成只读预检、unit 校验、启用和系统实际触发时间核验。使用用户级 systemd，不依赖当前对话、临时 sleep 或 tmux 存活。生成器仅支持 Linux；其他系统先使用对应的持久调度器，不能把 Linux 文件生成成功当成已安排。

代理必须进入实际执行进程及其子进程，大小写变量一并继承，包含已有的 NO_PROXY。脚本从当前环境复制配置；若本机代理仅配置在 shell 文件或另一应用内，先读取本机配置补到启动环境。环境文件权限为 0600；回报变量是否存在，不输出代理地址、凭据或环境文件内容。

## 执行和回报

- 执行器仅在有效时间窗口内提交指定 ID。每次重试复用保存的 UUID；不换卡、不新建幂等键、不删除 attempt 或 receipt 来“重试”。文件锁防止并发兑换。
- 轮询模式只识别 10080 分钟的每周窗口，在每次提交前再次确认 `usedPercent` 为 100；回执、监控截止或恢复窗口结束后自动停用 timer。失败或未知回执不会换卡；查询状态见 `watch-status.json`。
- 读取 `receipt.json` 的原始 `outcome`：`reset` 表示本次已重置；`alreadyRedeemed` 表示同一幂等请求此前已兑换；`nothingToReset` 表示没有需要重置的窗口；`noCredit` 表示没有可用卡。后两者结束本次任务，不能报告“已使用重置卡”。
- 连接中断且没有确定回执时，报告结果待确认。只在同一卡、同一幂等键和原执行窗口内恢复；先查状态，避免把未知结果当作失败重新消费。
- 提交后的刷新用于验证当前额度，刷新失败不重新兑换。timer 触发、service 退出码为 0、日志出现 `verified` 都不能代替兑换回执。
- 查询/取消/改期步骤及保留哪些证据见 [references/timers.md](references/timers.md)。取消后核对 timer 和 service 状态；已被服务端接受的请求无法用停止 timer 撤回。

完成安排时给出卡片选择、执行时间或检查频率、到期和监控截止时间、任务名及配置/状态目录。只有验证 timer 已启用且触发设置正确后才说“已安排”；若首次检查已使任务结束，则核对 timer 停用状态并按回执报告，实际是否使用以执行后的回执为准。
