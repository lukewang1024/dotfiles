# Shared Hyper shortcuts

`keys.json` is the source of truth for physical chords, application roles,
layouts, and menu actions; `locales.json` holds the shared English/Chinese UI
catalog. Native input tools feed platform action adapters; H+0 uses the required
resident Rust palette through a Python bridge. Generated shortcut tables remain
committed, while H+0 additionally needs Python and the pinned renderer artifact.

Shift+0–9 are unbound. Hyper no longer owns virtual-desktop shortcuts; i3's
native Super+numbers remain unchanged. Existing letter-key aliases are retained.
H+0 edits `keys.json` in a text editor; after changing bindings run
`python3 config/hyper/generate.py`, then reload the platform adapter.
Role-app choices apply immediately without generation.

On macOS H+6/7 list live CoreAudio devices and mark the current device; selecting
one changes the default. H+0 → D/F open System Settings, without changing settings
automatically. H+3 offers an explicit enable action when memory-only text history
is off; collection starts only after opt-in (no earlier history is available).
The macOS collector reads Alfred's clipboard `blacklist` from its configured
sync folder (falling back to the dotfiles/local Alfred preferences) once on first
use and persists that snapshot in Hammerspoon settings. Reloads reuse it; there
is no periodic synchronization. Use H+0 → B (Sync Alfred clipboard blacklist)
to import later changes; failed imports retain the previous rules. It does not
read Alfred's clipboard database or modify Alfred
preferences. Password managers are additionally excluded by name/bundle ID,
including MacPass, 1Password, Passwords, Bitwarden and KeePassXC. Concealed,
transient, autogenerated and 1Password pasteboard types are rejected before
reading text. `hyper.clipboardExcludedApps` in Hammerspoon settings can add
names or bundle IDs. Application-deactivation checks cover quick app switches;
macOS does not guarantee source attribution, so this is defense in depth, not
a guarantee against unmarked background copies or browser-extension secrets.
These rules apply to Hyper's macOS collector, not external Windows/Linux tools.
Windows uses native clipboard/screenshot interfaces, Snipping Tool for recording,
and [documented Settings URIs](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-settings)
for audio, displays and Focus Assist. Recording is an entry point, not auto-start.
Linux audio uses `pavucontrol --tab 3/4`, displays use `xfce4-display-settings`
or `arandr`, and focus opens `xfce4-notifyd-config`; GNOME/settings-manager
fallbacks are used when installed. [pavucontrol supports selecting a tab](https://manpages.debian.org/bookworm/pavucontrol/pavucontrol.1.en.html).

Application toggles launch absent applications, show background applications,
and hide the frontmost application. Mac uses native application hiding.
Windows records only windows it minimized, preserving their maximized state;
Linux records only windows it hid, preserving workspace and geometry. Previously
minimized windows are not restored as part of that group. A Linux web-only
entry opens its URL and never hides all browser windows.

Shift application keys are explicit app shortcuts, not role-selection menus.
The Q/W, A/S, and X/C neighborhoods group browsers, AI apps, and communication
apps; the fixed direct keys do not change when role preferences change. The
Shift+number row is unbound, while the unshifted number row retains the window,
application, clipboard, capture, audio, and configuration menus. ChatGPT and
Doubao use the configured native/web definitions for their platforms.
Windows distinguishes Feishu chat and meetings by exact window class and title;
when no matching window exists, the shortcut launches Feishu. Linux currently
has no dedicated meeting-window definition.
On macOS, direct app shortcuts prefer the configured bundle ID, with a cached
installed-name fallback when the local bundle uses a different identifier.
The role picker remains available from H+Shift+/ and H+0 → A, but the QWEASDZXC
application keys are fixed direct shortcuts. H+R defaults to Windows App on
macOS (its installed bundle ID is still `com.microsoft.rdc.macos`), Windows
Remote Desktop on Windows, and Remmina on Linux. H+Shift+R launches Reeder on
macOS; other platforms report that it is unavailable. H+Shift+N launches
NoMachine independently of the remote-role default.
H+Space discovers applications from the local machine instead of presenting
the configured catalog as if every entry were installed:

- macOS: `.app` bundles in `/Applications`, `/System/Applications`, and
  `~/Applications`; names and IDs come from actual bundle metadata. Python 3
  scans in a background task, and Hammerspoon keeps results in memory.
- Linux: XDG application directories, respecting user overrides, Hidden,
  NoDisplay, TryExec, and desktop visibility. Entries launch with `gio launch`.
- Windows: the native `shell:AppsFolder` collection, cached in memory.

Results refresh every 10 minutes (on the next search for Linux/Windows).
Mac/Linux also keep a disposable index in `$XDG_CACHE_HOME/hyper/apps-*.json`.
Reloading Hammerspoon refreshes its index asynchronously; an immediate manual
refresh is `workbenchHyper.apps:refresh()` in its console. Trae is not a static
candidate: if installed, it is discovered under its real local name and path.
Discovered Linux/Windows apps use the OS launcher; the fixed app shortcuts
retain their existing show/hide toggle semantics.

Display direction uses a 90-degree sector from monitor center. Left/right keys
fall back to the vertical axis if there is no horizontal peer, so vertically
stacked screens remain reachable without separate up/down screen shortcuts.

Window operations use direct shortcuts, not a window menu. H+apostrophe is
unbound; H+semicolon now toggles the primary terminal (Shift selects the secondary).
The Enter and backtick terminal bindings, including their Shift variants, are
retired; ordinary Enter still confirms menu selections. H+W toggles work chat. Resizing uses the
bracket keys without a mode or menu. On landscape displays, quarter placement uses H+Left/Right followed
by H+Up/Down. On compact Mac keyboards, Fn+Left/Right provides Home/End and
Fn+Up/Down provides PageUp/PageDown.

Menus capture their target before opening UI. Search menus use text filtering
and Enter; system/capture menus also have direct keys. Mouse movement is direct.

Hyper menus use the standalone Rust Alfred-style panel: at most nine visible rows,
shrinking with the result count while the search field stays anchored. H+J/K
select rows; H+H/L edit the query. Quick menus align action names and direct keys
in separate columns; press `/` to search instead. H+/ shows the function as the
title and the shortcut underneath, searchable by function name or action ID.
The resident Rust renderer owns presentation and focus; platform adapters supply
menu data and execute actions. The retired WebKit styling settings no longer apply.
Window restore/undo geometry follows the destination work area on screen moves.
H+= is retired. Windows forwards the four window arrows to native Win+arrows on landscape displays,
including the OS's own Snap state behavior. macOS/Linux implement maximize,
restore/minimize, halves and vertical half/quarter transitions, not Snap Assist
or native cross-monitor cycling. On portrait displays Left/Right place top/bottom
halves on all platforms; Up/Down retain maximize, restore and minimize behavior
without the landscape half/quarter transitions. PageUp/PageDown remain optional
fixed top/bottom shortcuts, not required on compact keyboards. A maximized
window returns to its preceding layout. Left/right halves go to the respective
upper/lower quarter with Up/Down; the reverse direction returns a quarter to
its half. Down from a lower quarter restores the pre-snap frame; Down from a
normal window minimizes it. Up first restores the most recently Hyper-minimized
window, skipping closed or already restored windows. This stack does not track
windows minimized through other tools or survive Mac/Windows adapter reloads.
Manual resizing invalidates tracked snap/maximize state.
If a window was already maximized before Hyper observed it, macOS/Linux fall
back to an 80%-size centered window because its original frame is unavailable.
On i3, minimize uses the scratchpad; app focus brings it back.

### Thirds and two-thirds

All five proportional placements are shared across platforms, in two cycles:

The current window's display work area determines orientation: height > width
is portrait; square areas use landscape behavior. `adaptiveLayouts` in `keys.json`
defines which layouts transpose their x/y and width/height fractions. Portrait
cycles are top/bottom 2/3 and bottom/middle/top 1/3. Fixed PageUp/PageDown layouts,
screen-switching shortcuts and maximize/restore/minimize do not rotate.

| Shortcut | Cycle |
| --- | --- |
| H+Shift+Up | Left 2/3 → right 2/3 → left 2/3 |
| H+Shift+Down | Right 1/3 → middle 1/3 → left 1/3 → right 1/3 |

Cycles compare the current window's actual frame with the current screen's
work area, allowing for pixel rounding. A window outside the chosen cycle enters
its first position; one already in a cycle advances to the next. There is no
global counter: changing windows, manual resizing, undo or moving to another
screen cannot leave a stale cycle index. H+Backspace undoes the last placement.

These commands place the current window only; they do not rearrange other windows.
FancyZones is optional on Windows. A three-column Grid can span adjacent zones
to produce either two-thirds placement. Leave its **Override Windows Snap** off
to retain the native Win+arrow behavior used by Hyper. The relative-position
override changes all four arrows to zone navigation, including Up/Down.

### Configure role applications

Press **H+Shift+/**, or **H+0 then A**, to open role settings. The same action is
searchable in H+Space and H+/. Pick a role, then an application; saving changes
its role action immediately without launching the app or reloading the desktop.
Roles without a shortcut are available as actions in **H+Space**; H+/ lists
only bound shortcuts.
Esc cancels without changing the mapping. Each role lists its shortcuts and
current application, and the picker includes a **Use default application** entry.

All roles are editable, including the primary and secondary terminals, browser,
editor, files, work/daily chat, AI, notes, music, passwords, remote, Git and docs.
Explicit application keys such as H+Shift+W for Chrome remain fixed; changing a
role preference does not change the QWEASDZXC direct shortcuts.

The picker includes platform-supported configured apps plus the cached installed
app index; it is not restricted to a role's suggested list. Configured entries
can be selected before installation. Discovered macOS bundles retain show/hide
behavior. Discovered Linux desktop entries use `StartupWMClass` when declared;
without it they launch only. Discovered Windows AppsFolder entries launch only
because that index does not provide a reliable window identity. These limitations
are labelled in the picker. Use a configured app entry for its existing toggle
behavior, or supply a native app override with a verified window identity.

Preferences are machine-local and preserve other settings:

- macOS: Hammerspoon's `hyper.defaults` settings.
- Linux: `$XDG_CONFIG_HOME/hyper/local.json`, `[defaults]` represented as a JSON object.
- Windows: `$XDG_CONFIG_HOME/hyper/local.ini`, falling back to `%APPDATA%/hyper/local.ini`.

The old `chat` preference is read as `workChat` when no explicit work-chat choice
exists. It never overrides `dailyChat`, whose default is WeChat. The legacy key
is retained rather than deleted. Restoring a role's default writes only that role.

### Language

Hyper's menus, action labels and built-in notices follow the system display
language: Chinese for `zh` variants, English otherwise. Both English and Chinese
function names remain searchable regardless of the displayed language. Installed
application names and window titles stay in their original form; external tool
diagnostics are not translated by Hyper.

- macOS uses the first preferred system language (not the current input source),
  refreshed when Hammerspoon reloads.
- Windows uses the user's UI language, not the keyboard layout.
- Linux uses the standard message-locale environment (`LC_ALL`, `LC_MESSAGES`,
  `LANG`, and `LANGUAGE`); `C`/`POSIX` uses English.

## Generate and validate

Run from the repository root:

```sh
python3 config/hyper/generate.py
python3 config/hyper/generate.py --check
python3 -m unittest discover -s config/hyper -p 'test_*.py'
luajit config/hammerspoon/private/tests/hyper.lua
luajit config/hammerspoon/private/tests/hyper-i18n.lua
luajit config/hammerspoon/private/tests/hyper-roles.lua
luajit config/hammerspoon/private/tests/hyper-rust-palette.lua
```

Generation updates the Mac Lua table, Windows AHK table, i3 include,
xbindkeys Hyper block, Rectangle export and key reference. It does not reload
any application. Retired `app-launch-toggle.lua`, `window-shortcuts.lua` and
`mod/capslock-mod.ahk` are legacy files; the current entry points do not load them.

## macOS

The dotfiles Hammerspoon entry point loads `private/modules/hyper.lua`.
Hammerspoon owns all Hyper window actions, so undo also covers direct layouts.
Rectangle may keep handling mouse snapping and its unrelated shortcuts.

Release Rectangle's old Hyper bindings once, then reload Hammerspoon:

```sh
python3 config/hyper/migrate_rectangle.py          # preview
python3 config/hyper/migrate_rectangle.py --apply  # backup, migrate, restart Rectangle if running
hs -c 'hs.reload()'
```

The migration backs up only affected preferences under
`$XDG_STATE_HOME/hyper/rectangle-*.json` (default `~/.local/state/hyper`).
Each saved entry can be restored with the `defaults write` command printed by
the migration. The regular Mac bootstrap also performs this migration.

Machine-local defaults and app definitions use Hammerspoon settings:

```lua
local preferences=hs.settings.get('hyper.defaults') or {}
preferences.browser='chrome'
preferences.workChat='lark'
preferences.dailyChat='wechat'
hs.settings.set('hyper.defaults', preferences)
hs.settings.set('hyper.apps', {docs={title='Docs', mac='com.apple.Dictionary'}})
```

Manual settings edits require reload; the role-settings UI applies changes immediately.
Text clipboard history is memory-only, capped
at 50 entries of at most 64 KiB, and starts recording only when enabled with
`hs.settings.set('hyper.clipboardHistory', true)`. It resets on reload.
Image sync reuses the existing workbench clipboard module and configured target.

The remote-window detector disables local Hyper bindings except escape while
a NoMachine/Windows App remote surface is focused. Existing F18 passthrough
remains in Karabiner. When Caps Lock is being forwarded as F18, the host escape
can be entered as physical Ctrl+Option+Command+Esc; the client must permit
host capture. Nested remote-client capture is not guaranteed.

Numbered Spaces/move-to-Space is intentionally an optional adapter: this
implementation shows Mission Control with an explanatory message, rather than
depending on experimental Spaces mutation. It does not move the window.

## Windows

Requires AutoHotkey **v1.1.33+**, matching this repository's existing script.
Run/reload `config/autohotkey/kbmod.ahk`; `mod/hyper-capslock.ahk` uses the shared
table and `lib/hyper.ahk`. Caps Lock and received F18 both activate the layer.

Machine-local overrides: `$XDG_CONFIG_HOME/hyper/local.ini`, or
`%APPDATA%/hyper/local.ini` when XDG_CONFIG_HOME is unset:

```ini
[defaults]
terminal=terminal
browser=edge
workChat=feishu
dailyChat=wechat
[launch]
feishu=C:\Users\YOUR_USER\AppData\Local\Feishu\Feishu.exe
code=C:\path\to\Code.exe
```

Paths may contain environment variables. Match executable names in `keys.json`
to the installed application. Unavailable executables report a launch error;
there is no automatic installation. Reload after editing overrides.

Hyper's number row is reserved for environment functions, not virtual desktops.
Application-native fullscreen is not emulated by sending F11 to arbitrary
applications. The window menu explains that limitation. Clipboard history uses
Win+V and its OS setting. Image sync needs a Windows workbench adapter and
currently reports that requirement. Recording opens Snipping Tool.

## Linux

This implementation targets the repository's **i3/X11 and other EWMH/X11
desktops**. It does not claim Wayland support. A Wayland session fails clearly
instead of attempting to manipulate XWayland windows as the whole desktop.
Native Hyprland/Sway adapters can reuse the same action IDs later.

`util/linux/hyper` owns shared application toggling, role selection, menus and
layout policy. `config/hyper/linux_desktop.py` supplies two X11 backends:
`I3Desktop` uses i3 IPC for workspace, scratchpad, floating and fullscreen
operations; `EwmhDesktop` uses wmctrl/xdotool for Xfce and other EWMH window
managers. Shared X11 discovery/geometry lives in `X11Desktop`. The factory
selects i3 only when its IPC responds; installing i3 alone does not select it.

Each application's `linux` object accepts these independent policy fields:

- `activation`: `focus` (default, follow the window to its workspace) or
  `summon` (bring it to the current workspace before focusing).
- `hide_on_active`: `true` (default) or `false` (the old i3run `-g`/nohide).
- `class` and optional `instance`: exact case-insensitive WM_CLASS filters;
  when both are set, both must match. The launch argv must create a matching
  window; this adapter does not rename arbitrary existing windows.
- `i3` / `ewmh`: optional overrides for that backend, including the fields
  above and `argv`. Other platforms do not use these overrides.

For example, an application's `linux` entry can be:

```json
{
  "class": "Thunar",
  "instance": "filemanagerA",
  "argv": ["thunar-launcher", "filemanagerA", "ThunarDetailsView"],
  "i3": {"activation": "summon", "hide_on_active": true}
}
```

The old `$grun` semantics are `activation: focus, hide_on_active: false`;
`$srun` semantics are `activation: summon, hide_on_active: true`. Current defaults
deliberately keep active-app hiding enabled as requested. Music, QQ Music,
WeChat and passwords use `summon` under i3, restoring their former `$srun`
behavior; EWMH defaults remain `focus`. Hiding/restoring still operates on the
matched application group, not i3run's single chosen container. Only windows
hidden by Hyper are restored, with existing saved workspace state retained.

Edit shared defaults in `keys.json`, or supply a complete application entry in
`~/.config/hyper/local.json` under `apps` for a machine-specific override.
Regenerate native tables after editing `keys.json`.

Backend unit tests run with the normal Python test suite. On a Linux host with
Xvfb, xterm and the relevant WM installed, run isolated real-window checks:

```sh
python3 config/hyper/validate_x11.py i3
python3 config/hyper/validate_x11.py xfwm4
```

These create temporary X displays and test windows, not the user's session.
Optional `--screenshot /path/to/evidence.png` requires ImageMagick's `import`.

The regular Linux bootstrap links `config/hyper` to `~/.config/hyper` and
`util/linux/hyper` to the configured bin directory. Required dependencies:
Python 3.9+, Hyper Palette, xdotool, wmctrl, xprop, xrandr, and i3-msg for i3.
Window geometry also uses `xwininfo` (from `x11-utils`/`xorg-xwininfo`) so
Xfce's client offsets and decorations do not distort halves/thirds. EWMH moves
wait briefly for the settled frame before recording restore state.
Arch/Debian GUI package lists include the X11 tools. Tkinter is not required.
Screenshot/record/history/system entries also use existing desktop tools such
as flameshot, dmenu-record, rofi/greenclip, lxtask, and the `lock` helper.

i3 uses the generated block embedded in `config/i3/config` (also compatible
with i3 4.16, which predates `include`); `config/hyper/i3.conf` remains available
for custom configs on newer i3. Non-i3 X11 sessions use the generated
block in `.xbindkeysrc`. Run only one binding owner per session. Reload i3 or
run `kbmod` in the non-i3 session after installation. xcape and `.Xmodmap`
continue providing Caps Lock/Esc and received F18/Hyper_R behavior.
The old Escape/Mode_switch navigation layer is retired: Escape is ordinary
Escape, while Hyper owns editing and mouse navigation. Reload `.Xmodmap` via
`kbmod` when upgrading; leaving duplicate arrow keysyms on H/J/K/L breaks
X11's key lookup for both bindings and injected navigation keys.

Input repeats invoke xdotool directly, without starting the Python adapter.
Layouts in i3 explicitly switch the target to floating; undo restores its
previous floating/tiling state and geometry, but not its exact old tiling-tree
position. Core Super/i3 shortcuts remain available.

`~/.config/hyper/local.json` supports local defaults and replacement app entries:

```json
{
  "defaults": {"terminal":"alacritty", "browser":"firefox", "workChat":"feishu", "dailyChat":"wechat", "clipboardTarget":"node-id"},
  "apps": {
    "firefox": {"title":"Firefox ESR", "linux":{"class":"Firefox-esr", "argv":["firefox-esr"]}}
  }
}
```

Commands are argument arrays, not shell strings. State is private JSON under
`$XDG_STATE_HOME/hyper`, separated by DISPLAY; window titles and clipboard
contents are not stored there. Apps that started minimized remain minimized.
Bindings execute on the desktop owning the keyboard; a nested remote viewer
must release/pass through capture using its own controls.

## Terminal boundary

The old tmux root Shift+Left/Right window bindings were removed so they cannot
intercept selection chords. Prefix+comma/period still switches tmux windows.
Terminal applications and tmux copy mode keep their own selection semantics;
Hyper's emitted Shift+arrows do not invent a universal terminal selection mode.

## Acceptance checks on each desktop

1. Toggle an app with two visible windows and one pre-minimized window; only
   the two newly hidden windows should return, focused as before.
2. Cycle H+Shift+Up twice and H+Shift+Down three times, checking the order;
   change windows/screens and undo, then verify the next step uses actual geometry.
3. Maximize and restore; place halves and quarters using the arrow keys.
   Confirm H+W toggles work chat, H+C toggles daily chat, and semicolon/apostrophe no longer resize windows.
4. Hold H+L; ensure one continuous cursor movement, no extra step on release.
5. Move between offset displays; verify edge wrapping, other-axis fallback, and the single-screen warning.
6. Hold H+Shift+HJKL to move the mouse without a menu. Use the bracket keys to
   adjust width/height; check Home/End and PageUp/PageDown actions, including Shift.
7. Check remote Caps/F18 behavior with the actual client and remote endpoint.
8. Open H+Shift+/, change a role, launch/hide it with its normal shortcut, reload
   and verify persistence; reset that role without affecting other preferences.

Unit checks do not substitute for these native Windows/Linux acceptance checks.
# Required Rust palette for all Hyper menus

All Hyper menus require the standalone [Hyper Palette](https://github.com/lukewang1024/hyper-palette).
The HTML/WebKit, AHK GUI and Tkinter renderers have been removed; there is no
legacy fallback. Dynamic pages retain the same window and parent search state;
continuous actions do not dismiss the palette. Python 3.7+ is required for the shared bridge (Windows also needs
`pythonw.exe` on PATH). macOS uses Hammerspoon; Windows uses AutoHotkey v1.1;
Linux uses the existing X11 adapter.

The exact CI run, commit, protocol and archive SHA256 values are pinned in
`palette-build.json`. Download that run's target artifact with `gh run download`,
then install its inner ZIP from the repository root:

```sh
python3 -B config/hyper/install_palette.py /path/to/hyper-palette-0.1.0-TARGET.zip --target TARGET
```

Use `python` on Windows. Targets: `aarch64-apple-darwin`, `x86_64-apple-darwin`,
`x86_64-pc-windows-msvc`, `x86_64-unknown-linux-gnu`. The installer verifies the
hash and manifest before replacing anything. It stops the resident renderer,
keeps the prior installation in `previous-*`, and restores it if activation fails.
Reload Hammerspoon / restart the Dotfiles Hyper scheduled task after adapter updates.

Install the renderer before reloading updated adapters: they require the
`dynamic_pages` capability and deliberately reject older renderers. Native OS
settings, capture and clipboard panels remain native; the removed renderers
were the Hyper-owned menu windows, not those system applications.

With an unlocked desktop, run `python3 -B config/hyper/validate_palette.py`
to exercise the installed authenticated bridge, lazy child pages, continuous
actions, parent navigation and final dismissal. It uses synthetic menu items
and does not execute application/window/clipboard actions.

The bridge keeps one renderer warm per desktop session. Only whitelisted action
IDs return to the platform adapter; the renderer does not execute shell commands.
Menu requests use authenticated, size-bounded JSON over loopback. Diagnostics are
in `$XDG_STATE_HOME/hyper-palette/*/host.log` (Windows defaults to
`%LOCALAPPDATA%/hyper-palette`). Installation lives in
`$XDG_DATA_HOME/hyper-palette/current` (same Windows fallback).

Theme follows macOS/Windows native events and Xfce/GNOME settings on Linux.
Xfce uses its GTK theme name; custom dark themes without `dark`/`black` in the name
and other Linux desktops are not yet covered. Existing `--dark`/`--light` flags
are renderer diagnostics, not the default integration behavior.
